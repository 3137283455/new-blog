# 后台流量监控入口

后台左侧「媒体库」下方新增「流量监控」，点击后直接在后台右侧显示完整监控面板，复用博客管理员登录。

## 部署

执行原来的 `bash scripts/deploy.sh --pull`。监控代码已经随博客打包，后端会自动启动并管理本机 Python 监控进程，不需要另行克隆仓库、配置访问地址或部署 Docker。需要 Python 3.11+，脚本会检查版本和时区数据库。

通过博客域名或原来的 `:3002/admin` 都能使用。所有页面和接口通过同源 `/api/traffic/` 接入，现有 `/api/` 转发继续生效，无需新增 Nginx location。原型中的独立 `/traffic/` 跳转已撤销。

监控使用独立数据库 `backend/data/traffic-monitor/traffic.sqlite3`（路径跟随 `DB_PATH` 所在目录），保留节点、流量、账期和提醒，重启不清空。端口默认 `127.0.0.1:8098`，不向公网暴露。后台通过短期 HttpOnly 会话访问。

新节点默认使用 **SSH 加密拉取**，不需要购买域名、证书或新增服务器。博客服务器需要 OpenSSH 客户端；部署脚本会检查，Debian / Ubuntu 的 root 部署会自动安装缺失的 `openssh-client`。原采集器 HTTPS 上报节点继续兼容，不会自动切换方式或清空历史。

## 添加自己的节点

工作方式：VPS 本机运行 vnStat 保存网卡流量 → 博客每 5 分钟通过 SSH 读取五分钟记录 → 复用原来的账期计算、图表、CSV、期初补录与额度提醒。统计是网卡用量估算，不保证与 VirNAT 最终账单完全一致。

1. 后台 → 流量监控 → 页面顶部「添加节点」。这里管理的是能 SSH 登录并安装软件的 VPS；只有机场订阅／代理链接、没有服务器管理权限的节点无法接入。
2. 采集方式保留「SSH 加密拉取」。填名称、VPS IP、SSH 端口（VirNAT 填共享 IP 与分配的 **SSH 外部映射端口**，不是代理端口），网卡保留 `auto`，查询用户名保留 `traffic-monitor`。
3. 按订单填写额度、计费方向、重置日和时区；不确定时选择「套餐暂未确认」。
4. 保存后出现「SSH 拉取接入」。复制接入命令，在你已登录的这台 VPS 的 SSH 终端执行（Debian / Ubuntu + systemd，需要 sudo / root）。脚本会安装 vnStat、自动识别公网网卡、保留至少 72 小时五分钟记录，并配置专用查询账号与公钥。不会重启 SSH、代理或防火墙。
5. 将命令最后输出的 **SHA256:…** 主机指纹填回页面，点击「保存指纹并测试拉取」。主机指纹用于防止连接到冒充的服务器，必须从你信任的 VPS 登录会话或服务商控制台获取。
6. 显示「SSH 已连通」即接入成功。新安装 vnStat 需要约 5–10 分钟生成完整五分钟记录；之后博客后台自动拉取，关闭浏览器也不会停止。节点卡片和「节点设置」都有重新接入、测试入口。

博客服务器必须能连接该 VPS 的 SSH 端口；若服务商限制来源 IP，请允许博客服务器 IP。脚本不会替你修改防火墙规则。配置的查询公钥带 `restrict` 和固定命令，只能读取指定网卡 vnStat JSON，不能开终端或端口转发。无需填写 SSH 密码、上传私钥，也不会把私钥发到浏览器。

私钥自动生成并保存在博客服务器 `backend/data/traffic-monitor/ssh/id_ed25519`（目录跟随 `DB_PATH`），目录权限 700、文件权限 600；迁移服务器时需要保护并迁移此目录，丢失密钥后需要重新执行节点接入命令。主机指纹会持久保存；不匹配就拒绝连接，不会自动信任新密钥。

### 常见问题

- 连接超时：核对共享 IP、SSH 外部端口与博客到 VPS 的网络连通性。
- 密钥认证失败：在正确的 VPS 上重新执行接入命令，检查 SSH 是否允许公钥登录及查询账号。
- 指纹不匹配：从 VPS 控制台核实；重装服务器可能换主机密钥，不要直接忽略校验。
- SSH 已连通但暂无流量：检查 `systemctl status vnstat`，等待首批五分钟记录。
- 数据库重建或网卡改变：保留原有来源变化提示，重复记录不会叠加计费；无历史记录的时段仍显示缺口。
- 旧节点改用 SSH：在「节点设置 → 修改节点与套餐」修改采集方式、填写连接信息并保存，然后完成 SSH 接入。原历史保留，旧上报令牌不能向 SSH 节点继续写入。

### 原采集器上报方式（兼容）

选择「原采集器 HTTPS 上报」时，仍使用节点安装包与独立令牌，需要可访问的 HTTPS 博客上报地址。保存后上传安装包并按弹窗中的命令执行；安装包包含令牌，不需要另下配置。需要重新下载时在节点设置重新生成令牌，并同步更新 VPS 配置。

### 博客只有 HTTP IP:端口

**直接选 SSH 拉取即可**，不需要设置 `TRAFFIC_PUBLIC_URL`，也不需要让 VPS 访问博客的 HTTP 接口。SSH 查询自带加密并校验主机指纹。但这不等于网页登录变安全：HTTP 后台的登录、操作和显示的命令仍可能被篡改，建议只在可信网络使用，或通过本地 SSH 隧道访问后台。

页面顶部「接入说明」随时可查看步骤。监控页采用后台卡片、字体与按钮样式，使用页内标签切换，不再显示第二套侧栏。长列表由后台主区域滚动，弹窗关闭后恢复原来的位置。

离开监控页会停止内嵌页面的刷新；服务端和 VPS 采集继续运行。博客离线缓存不缓存监控页面、接口或登录状态。

## 可选环境变量

- `TRAFFIC_PYTHON`：Python 可执行文件，默认 `python3`，部署脚本使用现有 Python 虚拟环境。
- `TRAFFIC_PORT`：本机端口，默认 `8098`。
- `TRAFFIC_PUBLIC_URL`：需要固定采集上报域名时填写 `https://你的博客域名`；默认使用管理员进入面板时的站点源。

## 验证

后端构建后运行 `node backend/scripts/test-traffic-monitor.js`，测试使用临时数据库验证完整接入流程，不修改实际博客或监控数据。Windows 可通过 `TRAFFIC_PYTHON` 指定 Python 路径。

`python3 -m unittest discover -s services/traffic-monitor/tests -v` 验证 SSH 主机校验、输入限制、去重、旧节点兼容、密钥生成与受限接入脚本。前端 `npm run test:ui --prefix apps/web -- traffic-monitor.spec.ts` 覆盖电脑/手机 SSH 接入及长列表滚动。远端接入仍需在实际 VPS 完成安装与连通性测试。

可在独立测试环境安装 `paramiko`，运行同一组 Python 测试时会额外验证真实 OpenSSH 客户端与临时回环 SSH 服务的加密连接；没有该测试依赖时自动跳过，不属于生产依赖。
